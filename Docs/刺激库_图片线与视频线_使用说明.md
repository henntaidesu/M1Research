## 1. 这套东西解决什么问题

要在两种刺激呈现方式中选一种用于正式采集：

| 线 | 呈现内容 | 生成方式 |
|---|---|---|
| **图片线** | 静态 360° 全景 | Qwen-Image 2512 + qwen-360 LoRA |
| **视频线** | 同一张全景"动起来"的 360° 视频 | 用上面那张全景做 Wan2.2 TI2V-5B image-to-video |

**两条线是成对生成的**：每个候选先出一张全景，再用这张全景生成视频。图片线用的静态图取自视频处理链的第 0 帧（同分辨率、同放大、同接缝处理）。这样两条线的内容、清晰度、色彩完全一致，**唯一差别是"动不动"**，比较结果才能归因到呈现方式上。

## 3. 操作流程

### ① 批量生成

1. 选条件（默认 5 个都选）和每条件数量。每条件 4 个就是 20 对。
2. 刺激时长默认 30 秒。视频按这个时长循环编码；图片线的展示时长也由播放端控制，与视频相同。
3. 点「开始生成」。生成在后端线程里跑，**关掉网页也不会中断**。
4. 生成顺序按条件交错（HVHA#1, HVLA#1, …），中途停止时各条件的数量也是均衡的。

**耗时参考（RTX 5090）**：一张全景约 1–4 分钟，一段视频（121 帧、1440×640）预计数分钟。20 对大约需要 1–3 小时，适合放到晚上跑。

### ② 刺激库（质检）

- 每张卡片可以预览图片（360° 查看器）和视频（平铺显示，便于检查接缝和瑕疵）。
- **质检是必须做的一步**：视频出现以下情况就标「剔除」，剔除的对不会进入播放列表：
  - 人物或物体畸形、明显闪烁
  - 0°/360° 处有接缝
  - 镜头在运动（会让人晕动）
  - 与条件明显不符
- 卡片上显示亮度、对比度、运动量，可以顺手检查各条件之间是否存在明显的亮度差异。

### ③ 播放控制

**手动播放**（调试、给导师演示时用）：

- 在刺激库里点「推到头显」，然后可以暂停、继续、跳转、切到灰屏、让受试者评分、停止。

**实验序列**（正式评定时用）：

| 参数 | 默认 | 说明 |
|---|---|---|
| 注视 | 5 s | 灰色全景 + 中央 "+"，作为该试次的面部基线 |
| 刺激 | 30 s | **头显确认开始播放后才开始计时**，保证每次实际观看时长一致 |
| 评分超时 | 0 | 0 表示一直等到受试者提交 |
| 恢复 | 10 s | 灰屏，让情绪回落 |

自评面板在刺激结束后才出现，包括：

- 愉快度 1–9（必填）
- 唤醒度 1–9（必填）
- 7 类情绪（可不选）

**分组（重要）**：受试者交替分到 **A 组、B 组**。

- 同一受试者每对刺激只看一种版本，避免同一场景看两遍造成熟悉化。
- A 组看图片的那几对，B 组看视频，两组互补。
- 「两种都看」只用于预览，不要用于正式评定。

**开始前的准备**：

- 实验前先点「头显预缓存全部刺激」，等顶部显示「已缓存 N/N」再开始。外网下一段视频有几十 MB。
- 序列运行期间，头显推来的 FEA 会同时写进 `runs/<run_id>/fea.csv`，用于计算面部表情反应。所以 `QuestProFaceCapture` 的 FEA 推送要保持开启。

### ④ 方案对比

比较的单位是**刺激对**：每对先在各条线内取平均，再算"视频 − 图片"的差，用符号翻转置换检验（配对设计，样本小也成立）。

| 指标 | 含义 | 地位 |
|---|---|---|
| 操纵命中率 | 自评落在该条件目标区域的比例（≥6 为高，≤4 为低；中性要求效价 4–6 且唤醒 ≤4） | **主指标** |
| 唤醒度 | 诱发强度 | 次要 |
| 效价极端度 | \|效价 − 5\| | 次要 |
| 面部表情反应 | 刺激期相对本试次注视基线的 70 维表情变化量（去掉眼球朝向和舌头） | 次要，直接关系到 FEA 数据集能不能采到信号 |
| 低层特征差 | 亮度、对比度、色彩度的配对差 | 混淆检查，应接近 0，只有"运动"一项应该不同 |

命令行版本：

```powershell
python CoreCode/backend/compare_stimlib.py
```

**建议的样本量**：至少 10 对（每条件 2 对以上）、8 名受试者（A、B 组各 4 人）后再看结论。界面会在样本不足时明确提示。

## 4. 数据落盘位置

```
DataSet/MyDataSet/Stimulus/lib/
  <pair_id>/meta.json        条件、场景、提示词、种子、模型、参数、低层特征、质检状态
  <pair_id>/pano.png         原始全景（存档）
  <pair_id>/still.jpg        图片线刺激
  <pair_id>/video.mp4        视频线刺激（H.264）
  <pair_id>/thumb.jpg
  ratings.csv                全部自评（run_id、受试者、分组、试次、刺激、V/A、7 类、作答耗时）
  runs/<run_id>/meta.json    播放列表、种子、参数
  runs/<run_id>/events.csv   阶段事件（服务器时钟）
  runs/<run_id>/fea.csv      该次运行的 FEA（服务器接收时间 + 头显时间 + 阶段 + 刺激）
```

`meta.json` 里的提示词、种子、模型文件名和全部参数可以直接写进论文方法部分，复现时用同样参数重跑即可。

## 5. 已知限制

- **视频没有声音**：Wan 只生成画面。如果预实验发现诱发强度不够，下一步可以给每个条件配环境音。两条线要配同一段音频，以保持可比性。
- **视频分辨率**：视频以 1280×640 生成后放大到 2048×1024，所以图片线也取同一处理链的帧，清晰度是一致的；但两条线都比原始全景（2048×1024 原生）略软。
- **两极区域**：全景模型和视频模型在天顶、天底附近都可能有轻微变形，质检时注意。
- **时间同步**：`fea.csv` 用服务器接收时间与事件对齐，外网延迟约几十到几百毫秒。对"整段刺激的平均反应"这个指标足够；但如果以后要做逐帧时序分析，需要改用头显时钟加同步事件。
