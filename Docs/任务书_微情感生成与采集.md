# 任务书：微情感驱动生成 + Quest Pro 同步采集

> 版本 v0.1（循环任务，逐 tick 实现）。归属 webFaceEmotionRec。
> 关联：[研究路线图.md](研究路线图.md)、[任务书_QuestPro_VR表情数据集采集.md](任务书_QuestPro_VR表情数据集采集.md)。

## 0. 一句话目标
新增页面「**微情感生成**」：摄像头实时识别用户微情感 →(情感变化)驱动 **ComfyUI** 生成对应风格的图像；同时输出**带时间戳的采集会话日志**，可与 **Meta Quest Pro** 的 70 维 FEA 流用 `DataSet/sync_quest_pro_capture.py` 离线对齐，形成「表情↔生成图↔FEA」多模态数据。

## 1. 情绪来源：Quest Pro 头显 FEA（默认）或 2D 摄像头
> **重要**：Quest Pro 不开放机内摄像头原始图像（隐私硬限制，WebXR 也拿不到），只提供
> **70 维 FACS 面部混合形状（FEA）**。所以「用机内摄像头」= 用 FEA 判情绪，而非读像素。

| 子系统 | 复用/新增 | 说明 |
|---|---|---|
| A 实时情感 | **Quest Pro FEA**（头显 Unity 侧 POST `/api/fea`，后端 `fea_emotion.classify_fea` 规则式 FACS→7类）；前端轮询 `/api/fea/latest`。**备选**：2D 摄像头经 `/ws/emotion` | 页面「数据来源」下拉切换 |
| B 情感→生成 | 复用 `comfyuiApi`（buildTxt2ImgWorkflow / server workflow）| 情感映射到提示词 → 生成图 |
| C 采集与同步 | 会话日志 + 同步打点；离线用 `sync_quest_pro_capture.py` | 与 Quest Pro FEA 按时间戳配对 |

### 数据流（头显模式）
```
Quest Pro Unity(QuestProFaceCapture) --POST /api/fea {blendshapes:[70]}--> 后端
   后端 fea_emotion.classify_fea → 存最近一帧
web「微情感生成」--GET /api/fea/latest(轮询300ms)--> 取 dominant/probs → 驱动 ComfyUI 生成
```
FEA→情绪当前为**规则式基线**（`backend/src/use_model/fea_emotion.py`，Ekman AU 组合），
将来可替换为 `train_multimodal_fer_vr.ipynb` 训练出的 FEA 分支（接口不变）。

## 2. 关键设计
- **触发策略**：`自动`模式下，dominant 情感变化且过冷却期（默认 ≥8s，防抖）→ 生成一张；`手动`模式下点按钮用当前情感生成。
- **情感→提示词**：每类情感一段风格描述（happy=明亮欢快抽象、sad=冷蓝忧郁…），可编辑；也可切到 VR 提示词库。
- **会话日志**（CSV）：`timestamp_ms, dominant, angry, disgust, fear, happy, neutral, sad, surprise, image_file, prompt`。
- **同步打点**：页面「同步打点」按钮 → 屏幕闪白 + 记录 `timestamp_ms`，供与 Quest Pro（Unity 侧同一动作）对齐时钟（写入 `offset`）。
- **Quest Pro 侧**：仍由 `QuestProFaceCapture.cs` 录 70 维 FEA（本页不改设备侧）；离线把本页 CSV 的帧时间戳与 FEA 流喂 `sync_quest_pro_capture.py`。

### 与 Quest Pro FEA 对齐步骤
1. 头显 Unity 应用每帧 `POST /api/fea {"blendshapes":[70],"timestamp_ms":..}`（顺序＝OVRPlugin.FaceExpression2）。
2. 本页头显模式即实时用该 FEA 驱动生成，并把每次生成写入会话日志（含 `timestamp_ms`）。
3. 采集离线数据时，头显侧另存 FEA 流；用页面「同步打点」+ Unity 侧同一时刻标记求时钟 `offset`；
   再用 `DataSet/sync_quest_pro_capture.py` 把 FEA 流与外接相机帧（如需图像）配对成样本。
