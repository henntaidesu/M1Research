## 整体流程

```
① 场景预设 → ② 生成图片 → ③ 选图 → ④ 实验流程 → ⑤ 运行实验 → ⑥ 数据
  (一次性准备，定好后所有受试者共用)                  (每名受试者一次)
```

①–④ 是**实验前的一次性准备**。定好之后，每来一名受试者，只需要在 ⑤ 输入编号、点开始。

---

## ① 场景预设

实验要用的场景：场景1、场景2、场景3……每个场景包含：

| 字段 | 说明 |
|---|---|
| 场景名 | 给人看的名字，如「黄昏海滩」 |
| 目标条件 | 这个场景想诱发的情绪区域：HVHA 愉快·兴奋 / HVLA 愉快·平静 / LVHA 不快·紧张 / LVLA 不快·低落 / NEU 中性 |
| 画面描述 | 生成图片用的提示词。中英文都可以，系统会自动加上 360 全景前缀。**不要写人物**，生成的人容易畸形，畸形本身就会引起厌恶 |
| 动态描述 | 只有生成视频版本时才用，图片实验可以不填 |

- 首次打开时自动建好 10 个默认场景，每个条件 2 个。
- 可以编辑、删除、上下调整顺序，也可以从 40 个内置模板里添加后再修改。
- **建议每个条件的场景数相同**（例如每个条件 2–4 个），否则各条件的样本量不平衡。

## ② 生成图片

- 选好场景，设定每个场景生成几张候选（默认 3 张），点「开始生成」。
- 生成在后端运行，**关掉网页不会中断**。实测一张约 2 分钟：10 个场景 × 3 张约 1 小时。
- 生成顺序是场景交错的（场景1#1、场景2#1、……），中途停止时每个场景都已经有候选。
- 视频版本是可选的，默认关闭，只有做「进阶：图片 vs 视频」比较时才需要。

## ③ 选图

每个场景挑一张作为正式刺激，点「选用」。挑选标准：

- 画面符合场景描述和目标条件；
- 没有畸形、明显的接缝或南北极扭曲，也没有人物；
- 各条件之间的亮度不要差太多。卡片上显示了亮度值，例如"悲伤 = 很暗"会让被试眯眼，面部数据就混入了亮度反应。

另外：

- 不合格的候选点「剔除」，剔除后不能被选用。
- 点「推到头显」可以戴上头显实际看一眼，这时需要头显在线、APK 已更新。

## ④ 实验流程

| 设置 | 默认 | 说明 |
|---|---|---|
| 包含的场景 | 全部 | 未选图的场景会标 ⚠，必须先选图 |
| 播放顺序 | **每人随机** | 推荐：每名受试者顺序不同，排除顺序效应；约束同一条件不连续超过 2 次。「固定」则按场景编号播放 |
| 静息基线 | 60 s | 整场开头一次，灰屏 + 指导语，作为个人面部基线 |
| 注视 | 5 s | 每张图前的灰屏 + "+"，作为该试次的基线 |
| 看图 | 30 s | **从头显确认显示的那一刻开始计时** |
| 自评超时 | 0 | 0 表示一直等到受试者提交 |
| 恢复 | 10 s | 灰屏，让情绪回落 |
| 表演校准 | 2 轮 × 7 类 | 静息之后，提示做某类表情并保持 4 s，标签 = 提示类别（`posed.csv`） |
| 7 类必选 / 强度 | 开 / 开 | 自评面板 7 类必选，并追问强度 1–5 |
| 每 N 个试次休息 | 0 | 建议设为试次数的一半；点「跳过」提前结束休息 |
| FEA 覆盖率下限 / 重看 | 0.8 / 开 | 不合格试次排到队尾重看一次（attempt=2） |

> 2026-11-19 新增上面四项及「续跑」、灰屏亮度匹配、全景朝向对齐，详见 [数据采集流程优化与刺激重建方案_2026-11-19.md](数据采集流程优化与刺激重建方案_2026-11-19.md)。
> 训练请改用试次级数据集：`python DataSet/MyDataSet/prepare_trial_dataset.py`（旧的滑窗脚本已修复标签错位）。

页面下方的「检查」会列出所有阻止开始的问题（未选图、场景已删除等），并估计整场时长。

## ⑤ 运行实验

**开始前检查**（页面上会显示 ✓ / ✗）：

| 项目 | 要求 |
|---|---|
| 头显在线 | 头显里的 App 已打开 |
| 面部数据 | > 20 Hz，正常应为约 60 Hz。不正常就检查 Quest 的「面部追踪」权限 |
| 时钟同步 | 显示了偏移量即可 |
| 实验流程 | 没有问题 |
| 刺激已缓存 | 点「让头显预缓存」，等显示 N/N 后再开始 |

**操作步骤**：

1. 输入受试者 ID（如 `p01`），种子保持 -1（随机，会记录下来）。
2. 帮受试者戴好头显，说明："看到画面时自然地看就好，不需要做表情；画面结束后用手柄选择你的感受。"
3. 点「开始实验」。头显里依次是：静息 → [注视 → 看图 → 自评 → 恢复] × 场景数 → 结束语。
4. 运行中可以暂停、跳过当前试次、停止。停止前会弹出确认，已采集的数据会保留。

**受试者的自评面板**：

- 愉快度 1–9（必填）
- 唤醒度 1–9（必填）
- 最接近的情绪（7 类，可不选）

## ⑥ 数据

- **实验会话**：每场实验的状态、已评数、FEA 帧数；点「查看」可以看每个试次的评分。
- **各场景诱发效果**：每个场景的平均愉快度、唤醒度、命中率和面部反应。命中率 = 自评落在该场景目标区域的比例。命中率低的场景说明图片没能诱发预期的情绪，应该换图或改描述（回到 ②③）。
- **用于训练**：数据已经是训练格式，可以直接切窗训练：

```powershell
python DataSet/MyDataSet/prepare_timeline_dataset.py --root DataSet/MyDataSet/Capture --out DataSet/MyDataSet/timeline_sliced
python CoreCode/backend/train_timeline.py DataSet/MyDataSet/timeline_sliced --loso
```

### 每场实验保存的文件

```
DataSet/MyDataSet/Capture/<受试者>/<会话 stim_日期_时间>/
  meta.json        受试者、流程设置快照、播放顺序与种子、FEA 帧率、时钟偏移、状态
  fea.csv          timestamp_ms（服务器时钟）, f0..f69, headset_ms, source   —— 60Hz
  events.csv       每个阶段的开始，以及头显确认、评分、跳过、暂停等事件
  stimulus.csv     每张图的实际显示起止（onset = 头显确认显示的时刻）
  selfreport.csv   每个试次的愉快度、唤醒度、7 类情绪、作答用时
```

**时间对齐**：头显以 60Hz 采集 70 维 FEA，每秒批量上传，同时用轮询往返时间估计头显与服务器的时钟偏移，把每一帧换算到服务器时钟。所以 `fea.csv` 与 `events.csv` 在同一条时间轴上；模拟测试中，3 秒的人为偏移被精确恢复。

## 建议的试运行

先用 2–3 个场景，把「看图」设成 10 秒，自己戴头显完整跑一遍。然后在 ⑥ 里检查四件事：

- FEA 帧数是否约等于时长 × 60；
- 每个试次都有评分；
- `stimulus.csv` 的 dwell 是否约等于设定的看图时长；
- 面部反应一列有数值。
