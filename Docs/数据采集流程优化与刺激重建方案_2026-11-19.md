# 数据采集流程优化与刺激重建方案

- 日期：2026-11-19
- 依据：[研究设计_FEA时序情绪识别与早期预测_2026-11-18.md](研究设计_FEA时序情绪识别与早期预测_2026-11-18.md)、[图片刺激实验_操作流程.md](图片刺激实验_操作流程.md)
- 本文分两部分：**A. 已经落地的采集链路改进**，适用于任何刺激，现在就能用；**B. 刺激部分重建方案**，用来替换静态全景图，待确认后分步实施。

---

## 0. 结论

1. **原来的数据有一处会让研究结论失效的标签错位**。自评在刺激结束后才提交，切窗脚本又按"最近一次已提交的自评"往前填充，结果第 k 个试次刺激期的 FEA 拿到的是第 k−1 个试次的标签。另外，LOSO 在测试被试上挑最佳 epoch，相当于在测试集上调参。这两处都已修复，见 A.1。
2. **采集效率的最大损失来自静态全景图本身，而不是流程**。一个人独自看静态风景几乎不产生外显表情。Quest Pro 上的同类研究（Domingo-Ajenjo 等，CHI'26 SAXR）显示，同样的人数，视频诱发出的有效表情片段大约是静态图片的 2 倍。生成图还有三个问题：清晰度只有头显能显示的约四分之一，接缝和两极没有处理，各条件的亮度和情绪严重混淆。
3. **推荐的流程是混合范式**（B.2）：表演校准、短动态面孔片段、事件锁定的 Unity 场景、带声音的常模 360° 视频。每人大约 45 分钟头显内时间，可得 55–68 个有标签试次，原方案是 20 个。

## A. 已经落地的改进

### A.1 标签与评测修复

| 问题 | 修复 | 文件 |
|---|---|---|
| 自评前向填充导致标签错一位 | 有 trial 列的会话改为**按 trial 绑定**：只有刺激呈现期 [onset, offset] 内的帧有标签，标签取同一 trial 的自评；滑窗必须完全落在同一试次的刺激期内；quality=bad 的试次整段丢弃；块 id 改为试次 | `DataSet/MyDataSet/prepare_timeline_dataset.py` |
| 没有按试次切分的数据集 | 新增 `prepare_trial_dataset.py`，输出 `trials.npz`（每行一个试次，带 mask、注视基线、V/A/7 类/强度、attempt、fea_cov）、`posed.npz`（表演段）、`subjects.json`（静息期的个人均值和标准差）。按研究设计 §3.7 剔除：有效帧不足 80% 的试次剔除，有效试次少于 14 个的被试剔除，默认不收录重看试次 | `DataSet/MyDataSet/prepare_trial_dataset.py` |
| LOSO 在测试被试上挑 epoch | LOSO 改为固定训满 epochs、取最后一个 epoch | `CoreCode/backend/src/use_predict/train_predict.py` |

### A.2 实验流程（后端 `use_stimlib`，网页「④ 实验流程」里可以设置）

| 功能 | 默认 | 作用 |
|---|---|---|
| 表演校准 `posed_reps` | 2 轮 × 7 类，每类保持 4 s、放松 3 s | 约 1.6 分钟得到 14 段带标签的表情，标签就是提示的类别，和 FEA 不同源。用于个人归一化，以及"表演 → 自发"迁移分析。写入 `posed.csv` |
| 7 类必选 `require_label7` | 开 | 原来不选 7 类的试次没有 7 类标签，直接浪费 |
| 强度 `ask_intensity` | 开 | 研究设计 §3.3 要求的第 4 项自评 |
| 长恢复 `long_recovery_arousal` | 唤醒度 ≥ 7 时恢复期延长到 30 s | 研究设计 §3.3，减少前一个试次对后一个的影响 |
| 休息 `break_every` / `break_s` | 关；建议设为试次数的一半，时长 120 s | 防疲劳；操作员点「跳过」可以提前继续 |
| 每试次质控 `min_fea_coverage` | 0.8 | 刺激期实际收到的 FEA 帧数除以应有帧数，写进 `stimulus.csv` 的 `fea_cov` / `quality` |
| 自动重看 `requeue_bad` | 开，最多 2 次 | 覆盖率不足或头显没确认呈现的试次，排到队尾再看一次，记 `attempt=2`，分析时可剔除。追踪偶尔掉线就不会白白损失一个试次 |
| 续跑 `resume_session` | — | 实验崩溃或中途停止后，在「⑥ 数据」里点「续跑」，只播还没有合格评分的刺激，不再做表演校准 |

落盘格式只在列尾追加新列，原有列的顺序不变：

- `fea.csv` 追加 `conf_lower, conf_upper`（SDK 给出的下半脸 / 上半脸置信度）
- `stimulus.csv` 追加 `attempt, fea_cov, quality`
- `selfreport.csv` 追加 `intensity, attempt`
- 新增 `posed.csv`：`onset_ms, offset_ms, emotion, rep, fea_cov`

### A.3 头显端（`StimulusPlayer.cs`）

- 新增阶段：`posed`（提示"请做出「开心」的表情并保持"）、`posed_relax`、`break`。
- 自评面板增加强度 1–5，7 类是否必选由后端下发。
- 每帧 FEA 附带上 / 下半脸置信度。
- **亮度匹配**：注视、自评和恢复阶段的灰屏亮度设为该试次图片的平均亮度。原来固定用 0.5 灰，切到很暗的负性图时亮度突变，会引起眨眼和眯眼，Eyes_Closed、Lid_Tightener 通道会把这当成表情记下来。视频暂时仍用 0.5。
- **朝向**：刺激出现时，把全景正中转到受试者当前的头部朝向。原来固定朝世界 +Z，主要内容可能落在受试者身后。
- Unity 6000.0.85f2 批量编译 0 错误；真机还没有测试。

**需要重新打包 APK。** 旧 APK 也能用：遇到新阶段会显示"+"，但看不到表演提示，也不会上传置信度。

### A.4 已验证

- 用模拟头显在进程内跑了一整场（静息 → 表演 7 段 → 4 个试次 → 休息 → 重看）：故意断 FEA 的试次 `fea_cov=0.0`，被判为 bad 并以 attempt=2 重看；唤醒度为 8 的试次恢复期按设定延长；各 CSV 的列都正确。
- 两个切分脚本都读取了这场的输出：bad 试次被剔除，重看试次默认不收录，滑窗全部落在合格试次的刺激期内。
- 前端 `npm run build` 通过。

## B. 刺激重建方案

### B.1 现在的刺激为什么差

**工程缺陷（可以修，但修完上限也不高）**

- 2048×1024 的等距柱状图，每度约 5.7 像素；Quest Pro 每度约 22 像素，戴上看是糊的。
- 图片线没做接缝处理，两极只靠负面提示词规避，实测仍有拉丝。
- 亮度和条件严重混淆：负性图的亮度约 0.05，正性图 0.4–0.9。
- 没有声音，没有事件。

**范式缺陷（修工程也解决不了）**

- 一个人被动地看静态风景：没有社交对象（Fridlund 的观众效应），也没有事件或任务。表情只在刺激出现那一刻有一点反应，然后很快适应。
- 按效价-唤醒四象限设计的场景诱发的是心境，不是离散情绪。愤怒和厌恶几乎拿不到（`conditions.py` 自己的注释也承认这一点）。

### B.2 推荐的混合范式（每人约 45 分钟头显内时间）

| 区块 | 内容 | 单个试次 | 数量 | 主要覆盖 | 标签 | 用途 |
|---|---|---|---|---|---|---|
| 0 | 静息 2 min + 表演校准 2 轮 × 7 类 | 7 s | 14 | 7 类 | 提示的类别（posed） | 个人校准；表演 → 自发迁移 |
| A | **短动态面孔 / 人声片段**：真人或虚拟人做出表情，配笑声、哭声、干呕声，正前方一块平面 | 注视 3 s + 片段 8 s + 快评 + 间隔 3 s ≈ 20 s | 7 类 × 4 | happy、disgust、surprise、sad | 自评 + 片段目标类别（target） | 模仿和情绪传染诱发最强；类别内用不同面孔，以检验 H5 |
| B | **事件锁定的 Unity 场景**：突然出现或巨响（surprise/fear）、虫子爬近（disgust）、奖励和礼花（happy）、不公平失败（angry）、悬崖边（fear）、平淡事件（neutral） | 事件前 5 s + 事件窗 8 s + 快评 ≈ 25 s | 约 30 | surprise、fear、disgust、happy、angry | 自评（felt），事件时刻由头显打点 | 事件时刻明确，最适合 RQ2 早期预测；配"只有动作"的对照版本 |
| C | **带常模的 360° 视频，有声音**（Li 2017 / CEAP-360VR，或 Jiang 2024 开源场景的被动版） | 注视 5 s + 45 s + 完整 SAM + 恢复 10 s ≈ 75 s | 10（4 个象限各 2 + 中性 2） | V/A；sad 主要靠这里 | 自评 + 常模 | RQ1 的 V/A 主任务；H5 的常模基线 |
| — | 休息 2 次，最后放一段正性视频 | | | | | |

- **快评**：在 9×9 情感网格上点一下给出 V/A，再选一个 7 类表情图标，约 4 s。完整 SAM 只在区块 C 使用。`rating_mode` 写进数据，作为协变量。
- **主评测只用自评标签（felt）的试次**；表演和模仿只用于校准和预训练。区块 A 的表情可能只是模仿、没有对应的感受，所以要按区块分层报告。
- **愤怒在 FEA 上本身就弱**：Domingo-Ajenjo 的结果里 anger F1 只有 0.19。论文中要预先声明。

### B.3 软件架构

**后端**

- 新增 `catalog.py`：统一的刺激清单，每个刺激一个 `catalog/<id>.json`，字段有 `kind / trial_class / asset / condition / target_emotion / norms / events / ethics_tier / habituation_group`。现有图片库自动映射成 `skybox_image` / `skybox_video`，id 不变。
- 新增 `trialtypes.py`：每种 trial_class 的阶段模板。`playback._seq_loop` 改成按模板执行；现在已经实现的表演、休息、重看、续跑直接复用。
- 新增 `builder.py`：生成播放顺序，约束包括类别平衡、同类型连续不超过 3 个、惊吓每场最多 3–6 次并且要隔开、拉丁方平衡、伦理同意过滤。
- `report()` 接收头显时间戳 `onset_headset_ms`，用与 FEA 相同的偏移量换算。新增 `/api/stimlib/events`，接收头显打点的事件时刻。

**Unity**

- 定义 `IStimulusPresenter`（Prepare / Begin / Tick / End）。拆出 `SkyboxImage`、`SkyboxVideo`（带声音）、`ScenePrefab`、`MimicryClip`、`PosedCue` 五个实现，`StimulusPlayer` 只保留轮询、对时、FEA 和分发。
- 场景 prefab 直接打进 APK，通过 Resources 里的注册表引用，先不用 Addressables；视频继续走现有的下载缓存。

### B.5 需要研究者决定的事

1. **360° 视频的来源**：
   - Li 2017（Stanford）托管在 YouTube，没有许可声明，只能实验室内部使用，不能随数据集分发；
   - CEAP-360VR 是 CC BY-NC 4.0；
   - Jiang 2024 的 Unity 场景开源，可以改成被动观看版本。
2. **惊吓类和欺骗类任务**（不公平失败）是否纳入：需要单独知情同意和事后说明，并在伦理申请中单列。
3. **模仿片段的素材**：使用已授权的动态表情库（例如 ADFES，需要申请），还是自己录制（演员签署授权）。
4. **ComfyUI 生成线的去留**：建议降级为补充素材，例如给事件场景做背景，不再作为主刺激。

### B.6 接口约定（v2，已实现）

- 刺激对象新增字段：`kind`（skybox_image / skybox_video / scene / mimicry）、`trial_class`（immersive / event / mimicry）、`rating`（full / quick / none）、`audio`、`prefab_key`、`target_emotion`、`events`（[{key, t_s}]，后端已按种子加抖动）、`params_json`、`duration_s`。旧 APK 忽略这些字段。
- 头显状态回报带 `onset_headset_ms`，后端换算后作为 onset，`stimulus.csv` 的 `onset_src` 列记录 headset / server / timeout。
- `POST /api/stimlib/events`：头显每 0.5 秒批量上报事件打点（evt:bang、complete、video_stall 等），写入 `events.csv`，`src=headset`。
- 新增刺激：在 `Stimulus/catalog/<id>.json` 写清单，素材放进 `catalog/assets/`，网页「④ 实验流程 → 其他刺激」里启用并勾选。新的 Unity 场景继承 `SceneStimulus`，再通过菜单「M1/Create Stimulus Scene Registry」建好的注册表登记 `prefab_key`。
